## 2. 결정한 내용 (보고서 권장안 적용)

- **공휴일 등록·수정·삭제:** 최고관리자·재무만 할 수 있다. 공휴일이 정산 보류 기간을 바꾸기 때문이다. 권한이 없는 등급에는 화면에서 버튼이 잠긴다.
- **후원자 차단 해제·잠금 해제:** 운영 등급 이상만 할 수 있다. 차단을 거는 일은 고객지원도 그대로 할 수 있다.
- **크리에이터별·전체 1건 금액 범위 변경:** 최고관리자·재무만 할 수 있다. 3차에서 정한 "돈 관련 정책은 재무" 원칙을 따랐다. 상한은 전역 1건 상한을 넘을 수 없다.
- **EMMA 수신 시각:** `EMMA_DB_TIMEZONE` 설정을 새로 만들었다. 비워 두면 기존 동작과 같다. EMMA DB 가 한국시간으로 기록하면 `Asia/Seoul` 로 설정한다. 첫 폴링 때 EMMA DB 의 시간대를 로그로 한 번 남긴다.
- **이체파일:** 은행에 그대로 올리는 파일이라 원문 숫자를 유지했다. 미리보기 화면에 "엑셀로 열어 저장하지 말 것"이라는 안내를 넣었다. 원천징수·세무 자료 CSV 는 식별번호를 `="004"` 형식으로 내보내 앞자리 0 을 지킨다.

## 3. 영역별 수정

### EMMA 수신 (P0)
- **P0-1** 폴러가 이제 SQL 에서 우리 대표번호로 온 행만 읽는다. 대표번호로만 온 답장은 UNKNOWN_ROUTE(안내 문자)로 처리하고 완료('9')로 마감한다. 다른 서비스 번호의 행이 수백 건 쌓여도 새 후원 문자 처리가 막히지 않는다. 건너뛴 비율이 높으면 경고를 남긴다.
- **EM-1** 수신 시각을 해석할 시간대를 설정할 수 있게 했다(바인드 파라미터로 전달). Prisma 어댑터가 시간대 오프셋을 버리는 문제도 함께 고쳤다.
- **P2-21b** emma-mo 크론은 자기가 건 잠금만 해제한다.

### 결제·문자 수신
- **PAY-1** 결제수단이 해지됐어도 진행 중인 거래가 있으면 결과조회·대사 경로로 보낸다. 출금이 없었던 것으로 확인된 경우에만 실패로 닫고 한도를 되돌린다.
- **PAY-2** 늦게 도착한 결과는 REQUESTED/TIMEOUT 상태의 거래에만 반영한다. 관리자가 취소로 확정한 건은 덮어쓰지 않고, 한도 되돌림·문자 발송도 다시 하지 않는다.
- **PAY-3 (카카오)** 네 가지를 고쳤다.
  - `partner_user_id` 를 등록과 승인 모두 후원자 ID 로 통일했다.
  - 5xx 응답을 받으면 결과조회로 넘긴다.
  - tid 를 저장해 조회·취소에 쓴다.
  - 금액은 `amount.total` 에서 읽는다.
- **PAY-4 (온기)** 주문 키를 후원 ID 로 통일했다. 상태값이 비었거나 금액이 다르면 승인으로 처리하지 않는다.
- **P2-1~4** 문제가 된 네 가지를 고쳤다.
  - PIN·확인 링크 실패 경로에서 속도 카운터를 되돌린다.
  - 상태 전이는 조건부(`transitionStatus`)로 하고, 실제로 바뀐 경우에만 이력을 남긴다.
  - 거래의 `requestedAt` 을 한도 예약 시각과 같게 맞췄다.
  - PIN 세션 저장은 유니크 충돌일 때만 경합으로 판단한다.
- **P2-5** 로그 마스킹이 `x-api-key`·cookie 같은 헤더도 가린다.
- **P2-6** MO 웹훅은 처리 중 예외가 나면 500, 처리 중인 건이면 503, 형식 오류면 400 을 돌려준다. 후원이 생기기 전에 실패한 ERROR 행만 재전송 때 다시 처리한다. 수신 행 생성 중 DB 오류가 나도 5xx 로 응답한다(통합 검토 보완).
- **P2-7** 승인·조회·취소·환불은 그 거래를 만든 결제사로 보낸다.

### 정산·세무
- **SET-1** 원천징수·세무 CSV 의 식별번호를 텍스트 형식으로 내보낸다.
- **SET-2 / P2-8** 수동 [지급 완료]도 이체파일 발급 시각(재발급했다면 마지막 재발급 시각)을 지급일로 쓴다. 재발급 시각 컬럼을 추가했다.
- **P2-9** 세무 일정은 기한마다 다음 도래분을 보여 준다. 간이지급명세서는 매월로 바꿨다.
- **P2-10** 범위를 벗어난 연·월로 세무 자료를 요청하면 400 을 돌려준다.
- **P2-11** 수동 지급 완료는 잠금 안에서 승인 상태를 다시 확인한다. 상태가 바뀌었으면 분개까지 트랜잭션째 롤백한다.
- **통합 검토 보완** 지급일이 속한 달의 원천징수 신고기한(다음 달 10일)이 이미 지났으면 정산에 `[수정신고 필요]` 표시를 남긴다.
- 과세유형 안내 문구를 "다음 정산 요청부터"로 바꿨다.

### 보안·권한·빌드
- **SEC-1** 다음 두 경우에는 서버가 뜨지 않는다.
  - 프로덕션 빌드인데 `APP_ENV=local` 이고, 로컬 미리보기가 아닌 경우
  - `APP_ENV=local` 인데 `APP_BASE_URL` 이 공인 주소인 경우

  테스트 로그인과 `/api/dev/outbox` 는 PC 에서 직접 접속할 때만 열린다. 터널로 들어오면 막히고, 필요할 때만 `ALLOW_DEV_LOGIN_ON_TUNNEL=1` 로 연다. `.env.example` 의 `APP_ENV` 기본값은 비웠다(미리보기 실행기가 local 로 채운다).
- **SEC-2** 크리에이터 비밀번호 변경 시 입력값의 앞뒤 공백을 지우지 않는다.
- **P2-12** IP 를 알 수 없는 요청은 공용 버킷(개별 상한의 20배)에 넣고 경고를 남긴다. `CF-Connecting-IP`·`X-Real-IP` 는 설정을 켰을 때만 믿는다.
- **P2-13** 운영에서 공유 비밀 3종이 예시값이거나 `dev-only` 값이거나 32자 미만이면 서버가 뜨지 않는다.
- **P2-14** 시드 관리자 비밀번호는 `SEED_ADMIN_PASSWORD` 로 정한다. 없으면 무작위로 만들어 한 번만 출력한다. 운영 DB 에 공개된 시드 비밀번호가 남아 있으면 서버가 뜨지 않는다.
- **P2-15·20a·21a** 금액 범위 권한을 정리했다. `in` 검사 대신 `Object.hasOwn` 을 쓴다. 마지막 최고관리자 보호는 행 잠금으로 처리한다.
- **B-1** 공용 화면이 쿠키를 먼저 읽도록 바꿔, 빌드 환경에 DB 가 없어도 빌드가 성공한다.
- **B-2** CLAUDE.md 의 마이그레이션 안내를 실제 상황에 맞게 고쳤다.

### 오버레이·게임
- **OV-1** 토큰을 재발급하면 Redis 회수 채널로 모든 서버의 기존 연결을 끊는다. 이와 별도로 20초마다(게임은 2초마다) 토큰을 다시 대조한다.
- **OV-2** Redis 로 받은 게임 상태를 먼저 캐시에 반영한 뒤 화면에 보낸다. 더 오래된 상태는 버린다.
- **P2-16~18** 서버 TTS 처리를 세 가지 고쳤다.
  - 대기 상한을 12초로 늘렸고, 넘기면 브라우저 음성으로 대신 읽는다.
  - 알림이 끝나면 브라우저 음성도 멈춘다.
  - 음량은 한 번만 적용한다(클로바 volume=0).
- **P2-19** 개발 모드에서 룰렛이 돌지 않던 문제를 고쳤다.

### 화면
- **P2-20b** 결제 확인 화면의 카운트다운을 서버 기준으로 바꿔 hydration 불일치를 없앴다.

## 5. 알려진 한계

- **카카오 빌키:** 이전 방식으로 발급된 빌키는 `partner_user_id` 가 달라 승인이 거절된다. 아직 운영 발급분이 없으므로 영향은 없다.
- **게임 상태 순서:** 서버 시계로 판정한다. 인스턴스 시계는 NTP 로 맞춰 두어야 한다.
- **크론 잠금 해제:** 조회 후 삭제 방식이라 완전한 원자 연산은 아니다. cleanup 크론과 같은 수준이고, 실제 피해 가능성은 매우 낮다.
- **화면 렌더 테스트:** 화면 컴포넌트의 실제 렌더링은 테스트하지 않았다. 분리한 순수 함수만 검증했다.
- **기존 E2E 실패 36건:** 3차 보고서에 적은 문구 변경 관련 실패로, 이번 범위가 아니다.
