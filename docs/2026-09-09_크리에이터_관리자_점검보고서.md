## 1. 요약

기반은 견고합니다. 스튜디오 영역의 권한 경계, 개인정보 마스킹(전화번호·계좌·주민번호), 정산 원장 append-only, 지급 전 사전검증(`assertPayable`), 이체파일 배치번호 강제 등 지난 검수에서 지적된 치명 항목은 모두 코드에 반영되어 있습니다.

이번 점검에서 발견된 문제는 **"화면이 약속하는 것과 서버가 실제로 하는 것이 다른 지점"** 과 **"크리에이터와 관리자 사이의 업무 흐름이 끊어지는 지점"** 에 집중되어 있습니다. 돈이 새는 결함은 없으나, 정산 흐름이 관리자 개입 없이는 시작조차 못 하는 구조적 공백(H-2)과 정산 보류 기간이 표시만 되고 실제로는 적용되지 않는 문제(H-1)는 운영 전 반드시 정리해야 합니다.

|---|---|---|
| **치명** | 0 | - |
| **높음** | 7 | 업무 흐름 단절 · 화면/서버 불일치 · 데이터 덮어쓰기 · 심사 근거 누락 |

가장 시급한 세 가지:
1. **정산 계좌 실명확인 대기 큐가 없다.** 크리에이터가 계좌를 등록해도 관리자는 알 길이 없고, 인증 전에는 정산 요청이 막혀 있어 고객센터 문의 없이는 첫 정산이 영원히 시작되지 않는다. (H-2)
2. **"영업일 5일 후 정산" 안내와 캘린더가 표시 전용이다.** 실제 정산 가능금은 결제 직후 즉시 전액 요청 가능하다. (H-1)
3. **TTS 설정을 관리자와 크리에이터가 서로 다른 모델로 덮어쓴다.** 관리자가 저장하면 크리에이터가 고른 음성이 존재하지 않는 값으로 바뀐다. (H-4)

## 3. 관리자 연동 점검 결과

### 3.1 권한 구조

```
role=ADMIN + AdminProfile.permission
  SUPER_ADMIN ─ 전체 (관리자 추가/회수/권한 변경 전담)
  OPERATION   ─ 쓰기 + 운영(심사 상태·코드 재발급·MO 배정/회수) + 재무
  FINANCE     ─ 쓰기 + 재무(정산 처리·환불·수수료·계좌 인증) ; 이체파일 다운로드는 SUPER_ADMIN/FINANCE 만
  SUPPORT     ─ 쓰기(문의 답변 등)
  READ_ONLY   ─ 조회만 (run() 래퍼에서 차단)
```

- `requireWriteAdmin()` 이 허용목록 방식이고, `AdminProfile` 없는 ADMIN 계정을 차단한다. 정상.
- **M-1. `updateCreatorPaymentMode`(`actions/admin/accounts.ts:331-364`) 에 `assertOperationAdmin` 이 없다.** SUPPORT 권한으로도 크리에이터 결제 모드를 `DIRECT_TRIGGER` 로 바꿀 수 있다(서면승인·환경 플래그가 있을 때). CLAUDE.md 절대 규칙 7 이 다루는 가장 민감한 스위치인데 같은 파일의 심사 상태 변경(246행)·코드 재발급(540행)보다 가드가 약하다.
- `OPERATION` 은 정산 승인은 할 수 있지만(`assertFinanceAdmin` 허용목록에 포함) 이체파일은 받을 수 없다(`payout/route.ts` `ALLOWED_PERMISSIONS`). 의도라면 문서화가 필요하다.

## 4. UI/UX 개선 제안 (크리에이터 중심)

### 4.1 즉시 고쳐야 오해를 막는 문구·표시

1. **대시보드 mock 띠 조건화** (`studio/page.tsx:183-189`) — `env.payment.provider`·`env.mt.provider`·`env.youtube.provider` 중 mock 인 것만 골라 "결제는 mock, 문자는 실연동" 처럼 실제 상태를 쓴다. 유튜브 화면(`youtube/page.tsx:89-99`)은 이미 어댑터 모드를 읽어 처리하고 있어 같은 방식으로 맞추면 된다.
2. **정산 안내 정직화** (`settlement/page.tsx:228-264`) — H-1 을 서버에서 고치기 전까지는 "정산 예정일은 참고용이며 정산 가능금이 생기면 언제든 요청할 수 있습니다" 로 바꿔 화면이 사실을 말하게 한다.
3. **온보딩 체크리스트** (`onboarding-checklist.tsx:50, 67-73`) — "금액 구간을 최소 한 개 만들어야 효과가 재생됩니다" 는 사실이 아니다(구간 없이도 전역 설정으로 재생, `studio.ts:610` 주석, 같은 파일 81행 주석). URL 발급 여부로 판정하고, 대신 **"정산 계좌 등록"** 단계를 추가한다. 지금은 첫 정산까지의 경로가 체크리스트 어디에도 없다.
4. **상태 변경 알림 한글화** (`accounts.ts:312`) — `creatorStatusLabel[status].text` 를 쓰고 반려·정지에는 사유 입력칸을 붙여 본문에 담는다.

### 4.2 크리에이터 화면 기능 보완

5. **프로필 > 계정 보안** — 비밀번호 변경(현재 비밀번호 확인 + 전 세션 폐기), 로그인 기록 조회. `password-reset.ts` 의 세션 폐기 로직을 재사용할 수 있다. (M-10)

## 6. 부록 — 정상 확인 항목 (재검증 불필요)

- 스튜디오 서버 액션 25개: `withCreator()` 공통 래퍼, 내부 오류 메시지 일반화(`userFacingError`), zod 검증.
- 후원자 전화번호·계좌·주민등록번호·유튜브 토큰·TTS 시크릿: 저장 시 암호화/해시, 화면은 마스킹만. 주민번호는 앞/뒤 분리 전송, 신고 후 파기.

- 관리자 액션 전건 `writeAudit`(변경 전/후 값), 감사 기록 실패가 작업 실패로 보이지 않게 처리.
