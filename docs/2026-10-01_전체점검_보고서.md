## 2. P1 — 출시 전 반드시 고칠 것

### 후원·결제

**P1-1. 같은 후원에 PG 승인이 동시에 두 번 나갈 수 있습니다** `[확인]`
- 위치: `src/server/services/donation-flow.ts:976-1110`, `src/app/api/cron/cleanup/route.ts:111,170`
- `executePayment` 는 "완료" 와 "결제 불가" 상태만 막고, **진행 중(`PENDING_PAYMENT`/`PENDING_PIN`) 상태는 막지 않습니다.** 두 번째 호출은 같은 결제 트랜잭션 행(같은 주문번호)을 재사용해 PG 에 승인을 다시 요청합니다.
- 발생 경로: PG 가 느려 정리 배치가 잠금 시간(55초)을 넘기면 다음 배치가 같은 고착 건을 또 처리합니다. Redis 장애 시 배치 잠금이 `.catch(() => true)` 로 열립니다. 먼저 끝난 실행이 남의 잠금을 지웁니다(`kv.del`).
- 결과: PG 가 같은 주문번호를 중복 거절하면 **이미 승인된 건이 실패로 덮여** `PAYMENT_FAILED` 가 되고, 성공·실패 문자가 둘 다 나가며 한도 집계가 되돌려집니다. PG 가 주문번호로 중복을 막지 않으면 **실제 이중 출금**입니다.
- 수정: 판정 트랜잭션 안에서 상태를 조건부 `updateMany` 로 선점(또는 후원 ID advisory lock). 실패 갱신은 `status != 'APPROVED'` 조건부로. 배치 잠금은 소유자 토큰으로 해제하고 Redis 장애 시 실행하지 않음.

**P1-2. 장문(MMS) 조각이 늦게 오면 같은 문자에서 후원이 두 건 생깁니다** `[확인]`
- 위치: `src/server/emma/mo-poller.ts:213-271`, `donation-flow.ts:570`
- 180초 대기 후 도착한 조각만으로 처리할 때 **1번 조각이 없으면 2번 조각의 키가 멱등키**가 됩니다. 늦게 온 1번 조각이 처리되면 조각을 상태 무관하게 다시 모으므로 이번엔 1번 조각 키가 멱등키가 되어 **다른 후원으로 생성**됩니다.
- 결과: PIN 링크 두 번 발송, `DIRECT_TRIGGER` 모드에서는 즉시 두 번 출금(CLAUDE.md 절대규칙 4 위반).
- 수정: 장문 멱등키를 `ems:${emsId}` 로 고정하거나, 묶음에 완료('9') 조각이 이미 있으면 늦은 조각은 완료 표시만 합니다.

**P1-3. 운영에서 Redis 가 5초 남짓만 끊겨도 프로세스 재시작 전까지 영구히 죽습니다** `[확인]`
- 위치: `src/server/redis.ts:216`, `src/server/services/overlay-bus.ts:182`
- `retryStrategy` 가 6번째 재시도부터 `null` 을 돌려 ioredis 가 재접속을 포기합니다. 운영(인메모리 폴백 없음)에서는 클라이언트를 다시 만드는 경로도 없습니다. `redis-quiet.ts` 주석("운영에서는 클라이언트도 계속 살려 둬야 한다")과 반대입니다.
- 결과: ElastiCache 장애조치 한 번이면 이후 모든 MO 수신에서 한도 검사가 예외 → 후원이 `RECEIVED` 로 멈춤, 배치 잠금 우회(P1-1 악화), 오버레이 다중 인스턴스 전파 중단. **서비스 전체가 조용히 멈춥니다.**
- 수정: 운영에서는 지수 백오프로 무제한 재접속, 헬스체크에 Redis 상태 반영.

**P1-4. 강제 종료 직후 5~10분 사이 재처리되면 문자가 영구 유실됩니다**
- 위치: `donation-flow.ts:570-578`, `idempotency.ts:73-82`(10분), `donation-flow.ts:1399`(5분)
- 멱등키 획득 후 후원 생성 전에 프로세스가 죽으면, 수신 로그는 5분 뒤 풀리지만 멱등키는 10분 뒤 풀립니다. 그 사이 재처리는 `DUPLICATE`(연결된 후원 없음)로 반환되고 EMMA 폴러는 이를 완료('9')로 처리합니다.
- 결과: 후원자는 문자 요금만 내고 아무 안내도 받지 못합니다.
- 수정: `DUPLICATE` 인데 `resourceId` 가 없으면 `retryLater: true` 반환. 멱등키 해제 시간을 5분 이하로.

### 정산·세무

**P1-5. 이체파일 재발급 시 409 를 돌려주기 전에 배치번호를 이미 바꿔 버립니다** `[확인]`
- 위치: `src/app/api/admin/settlements/payout/route.ts:107-135`, `settlement.ts:780-825`
- `markPayoutFileIssued` 가 먼저 실행돼 재발급 건의 `payoutBatchNo` 를 새 번호로 덮고, 신규 건엔 발급 시각을 찍은 **뒤에** 409 를 반환합니다. 사용자는 파일을 못 받습니다. 화면에는 `confirmReissue=1` 을 붙이는 버튼이 없습니다(사용처 0건).
- 결과: B1 로 은행에 올린 건의 배치번호가 B2 로 바뀌어, 은행 결과파일(B1) 반영이 "배치번호 불일치"로 전부 거절됩니다. **실제 나간 돈이 원장에 기록되지 않습니다.** 섞여 있던 신규 건은 발급 상태로 갇힙니다.
- 수정: 재발급 여부는 읽기만으로 먼저 판정, 확정 갱신은 재발급이 없거나 `confirmReissue` 일 때만. 기존 배치번호 보존(이력 테이블). 화면에 재발급 확인 버튼 추가.

**P1-6. 부가세 과세표준·세금계산서에서 환불로 돌려준 수수료가 빠지지 않습니다** `[확인]`

**P1-7. 수동 "지급실패"·일괄 "지급완료" 가 배치 검증을 우회합니다 (이중지급 위험)**

- 수정: 이체파일 발급 건의 성공/실패는 결과 반영 경로(배치번호 일치)에서만. 일괄 PAY 는 `APPROVED` 만. 가드는 `balance - pending` 기준.

**P1-8. 원천징수 소액부징수를 요청 건별로 적용합니다 — 법령 확인 필요**

## 3. P2 — 중간

### 후원·결제
1. **후원 생성 뒤 예외가 나면 영구 미결 상태** — `donation-flow.ts:377-394, 781`. `RECEIVED`/세션 없는 `PENDING_PIN` 을 정리하는 배치가 없어 관리자 화면에 영원히 "진행중". → 일정 시간 지난 건 실패 확정 + 안내 문자 배치.
2. **MO 웹훅이 처리 실패·보류에도 200 응답** — `src/app/api/webhooks/mo/route.ts:101-112`. 사업자가 재전송하지 않아 유실(MTONET 구성). → 5xx 반환 또는 `ERROR` 행 재처리 배치.
3. **정지·탈퇴한 크리에이터가 문자 후원을 계속 받음** — `donation-flow.ts:448`(프로필 상태만 확인), `accounts.ts:64`(회원 상태만 변경). 웹 후원은 `user.status` 까지 확인함. → MO 라우팅·`executePayment` 에 `user.status === 'ACTIVE'` 검사, 정지 시 번호 회수.
4. **카카오 어댑터가 HTTP 5xx 를 승인 실패로 확정** — `adapters/payment/kakao.ts:298, 320-323`. 실제 승인됐을 수 있음. 조회 시 `tid` 자리에 우리 주문번호를 넣어 조회도 항상 실패. (현재는 레거시 확인링크 경로에서만 사용)

### 정산·세무·관리자
5. **부가세 별도 정책에서 세액 중복 계산, 과거 월에 현재 정책 적용** — `tax.ts:74-87, 108, 282`. 원장 금액은 항상 VAT 포함이므로 항상 `splitVat`. 분개 시점 공급가/세액 저장 권장.
6. **정산 계좌 실명확인 TOCTOU** — `accounts.ts:608-640`. 관리자가 A 계좌를 보는 사이 B 로 바뀌면 B 가 인증됨. → 폼에 `accountTail4`·`updatedAt` 포함, 조건부 갱신.
7. **세무 화면 "원천징수 신고 완료" 가 주민번호를 파기하지 않음** — `actions/admin/tax.ts:138-141`. 정산 화면 경로와 달리 `residentEnc` 가 남고 스튜디오가 재사용. "신고 후 즉시 파기" 안내와 불일치.
8. **원장 CSV 의 음수 금액이 문자열(`'-3000`)로 나감** — `api/admin/tax/export/route.ts:166-171`(이체파일 `csvCell` 도 동일). 엑셀 합계에서 빠짐. → 숫자 열 예외 처리.
9. **등급 가드 누락** — `transactions.ts:45`(`createMoNumber`), `accounts.ts:515`(`updateCreatorAmountBounds`), `:241`(`updateDonorLimitsByAdmin`). SUPPORT 등급도 실행 가능. → `assertOperationAdmin`/`assertFinanceAdmin`.
10. **과세유형 변경과 원천징수 확정 시점 불일치** — `settlement.ts:592-611`. 요청 뒤 사업자→개인 변경 시 원천징수 0원으로 지급. → 승인/파일 발급 시점 재확인.

### 인증·보안
11. **비로그인 인증번호 발송에 IP 제한 없음 (문자 요금 펌핑)** — `donation-lookup.ts:77-90`, `web-donation.ts:94-106`. 번호를 바꿔 가며 무제한 발송. → `consumeIpRateLimit(failClosed)` + 전체 발송 상한.
12. **SUPPORT 등급이 크리에이터 임시 비밀번호 발급 가능 (계정 탈취)** — `accounts.ts:95-125`. 정지·탈퇴는 OPERATION 이상인데 더 강한 조치가 열려 있음. → 대상이 CREATOR 면 `assertOperationAdmin`, 재설정 링크 메일 방식 권장.

### 오버레이·게임
13. **결과 발표 취소 창이 재발표마다 초기화 → 무한 재추첨** — `games.ts:406-459`, `game-studio.tsx:529-532`. 단축키 Backspace=취소, Enter=재추첨이라 방송 중 실수 위험. → 첫 발표 시각 기준, 취소 1회 제한, 재추첨 횟수 표시, Backspace 확인.
14. **첫 알림 수신 전 끊기면 그사이 후원 영구 누락** — `overlay-client.tsx:642`, `stream/route.ts:159,203`. → `ready` 에 커서를 담아 재연결 시 `since` 로 재전송.
15. **서버 TTS 안전시간 경과 후에도 음성을 멈추지 않아 다음 알림과 겹침** — `overlay-client.tsx:152-156, 421-436`. → `onplaying` 기준으로 세고 넘어갈 때 `pause()`.
16. **OBS 연결 상한(6) 초과 시 0.3초 간격 상호 끊기 반복** — `overlay-connections.ts:33,100-117`. 장면마다 소스를 넣으면 발생. → 밀려난 연결은 `evicted` 이벤트로 오래 대기, 상한 재검토.
17. **콤보를 표시명으로 세어 서로 다른 익명 후원자가 콤보로 묶임** — `overlay-client.tsx:519`, `overlay-combo.tsx:66`. → 후원자 해시 기준, 익명·테스트 제외.

### UI·UX
18. **예상치 못한 오류 메시지(영문 DB 오류)가 화면에 그대로 노출** — `actions/confirm.ts:49,102`, `actions/registration.ts:61,145`, `actions/studio.ts:66`. → 업무 오류만 노출, 나머지는 일반 문구 + 서버 로그.
19. **로그인 페이지가 주소창 `error` 값을 그대로 출력** — `login/page.tsx:40`. 가짜 경고 문구 위조(피싱), `?error=100%` 면 `URIError` 로 페이지 깨짐. → 정해진 코드만 표시.
20. **탭 제목에 "| 도네이도" 가 두 번** — `layout.tsx:47` 템플릿 + 24개 페이지가 직접 붙임. ("로그인 | 도네이도 | 도네이도")
21. **404 화면 없음** — `src/app/not-found.tsx` 부재로 Next 기본 영문 화면. **입력 오류 후 폼 내용 초기화(React 19)** — `support-form.tsx`(최대 2,000자), `limits-form.tsx`, 공용 `ActionForm`, `signup-form.tsx`. **입력란 label 누락·포커스 표시 약함** — 후원 패널·PIN 패널·주민번호 입력 등. **대비 부족** — `ink-400`(3.19:1) 이 글자색으로 406곳, 8~10px 글자 29곳.

## 4. P3 — 낮음·개선

**후원·결제**
- 결제 실패 시 속도 카운터를 다른 시간창에서 되돌림 (`donation-flow.ts:1237`, `limits.ts:385`) — 소비한 키를 저장해 그 키로 복구.
- 환불 시 한도 집계를 `paidAt` 기준으로 되돌림 (`refund.ts:256`) — `requestedAt` 기준으로.
- 환불 재시도 배치가 PG 장애 동안 매분 최고관리자 알림 생성 (`refund.ts:138, 335`) — 횟수 상한·백오프.

**정산·관리자**
- 세무 불일치 판정이 월 합계 기준이라 정상 건이 불일치로 표시 (`tax.ts:216`).
- 공휴일 액션이 허용목록이 아닌 거부목록(SUPPORT 만 차단) (`holidays.ts:21-25`).

**보안**
- 가입·크리에이터 신청에서 이메일 가입 여부 노출, 이메일 소유 확인 없음.
- 계정별 로그인 제한을 타인이 소진해 관리자 잠금 가능 (`login/route.ts:65-69`) — 계정+IP 조합.
- CSP 에 `frame-ancestors` 만 있음 — `script-src`/`object-src`/`base-uri` Report-Only 부터.
- 일부 상태 변경 API 에 `isSameOrigin` 누락 (`api/studio/games/**`, `api/studio/overlay/layout`, `api/admin/mt-templates`).
- IP 를 못 구하면 IP 기준 제한이 통째로 꺼짐 (`rate-limit.ts`) — 운영은 fail-closed.

**오버레이·게임**
- 마감·재개·종료가 조건 없이 상태 덮어쓰기 → 발표와 경합, 발표 뒤 참여 삽입 가능 (`games.ts:337-365, 633-658`).

- 남은 시간이 PC 시계 기준 (`game-overlay-client.tsx:401`, `play-client.tsx:90`) — 서버 시차 보정.

- 환불된 후원으로 자동 참여한 사람이 당첨 가능 (`games.ts:749-813`).

**UI·UX**
- 아이콘 규칙(size 16~20, stroke 1.6~1.7) 위반 약 300건, strokeWidth 미지정(기본 2) 다수 — 공용 `<Icon>` 래퍼나 린트 규칙 권장.
- `public-shell-client.tsx:75-82` 가 `aside` 를 받기만 하고 그리지 않음 — 11개 페이지의 사이드 안내가 보이지 않음.

- 모바일 메뉴에 `aria-current`·Esc 닫기 없음, 조회 시트 포커스 이동 없음.
- 용어 혼재: 크리에이터 관리자/스튜디오, 최고관리자/최고 관리자, 문자후원/문자 후원. 이메일 예시 `tornado@example.com`. 금액 placeholder 쉼표 없음. 크리에이터 화면에 `tx.provider`("mock"/"hecto") 영문 노출.
