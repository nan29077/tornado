# 게임 오버레이 화면 정리 — 겹침 · 시작 버튼 · 미리보기 진단

작성일: 2026-09-07

---

## 1. 스크롤하면 [게임 관리] 카드가 위 카드 밑으로 들어가는 문제

**원인.** 진행 컨트롤 카드를 화면에 고정(sticky)해 두었다.

```
sticky top-[헤더 높이 + 탭 바 높이]  z-20
```

원래 의도 — 예전에는 이 카드 **아래로** [내 게임] 목록과 [지난 게임 결과]가 길게
이어져 있어서, 스크롤을 내려도 진행 버튼(마감·발표)은 늘 보이게 하려던 것이다.

그런데 그 목록을 **팝업으로 옮기면서** 이 열이 짧아졌다. 지켜야 할 것이 사라졌으니
의도는 없어지고 **부작용만 남았다** — 고정된 카드가 그대로 서 있고, 아래 [게임 관리]
카드가 그 밑으로 미끄러져 들어가 절반이 잘린다. 창이 높아 스크롤이 생기지 않으면
겹치지 않으므로 "화면 비율에 따라 다르다" 로 보였다.

**고침.** 고정을 뺐다. 다른 카드와 똑같이 흐른다.

---

## 2. [방송에 시작] 버튼이 안 보이던 문제

지난 작업에서 게임 카드의 [방송에 시작]을 뺐다. 당시에는 그 목록이 진행 컨트롤
*아래*에 길게 붙어 있어 방송 중에 쓰기 어려웠기 때문이고, 띄우는 일을
[게임 바꾸기]·[게임 고르기] 팝업으로 옮겼다. **그 이유는 목록이 팝업으로 올라오면서
사라졌는데** 버튼은 돌려놓지 않아, "시작" 이라는 말 자체가 화면에서 없어졌다.

**고침 — 고르는 곳과 띄우는 곳을 같은 자리로 되돌렸다.**

[게임 관리] 팝업의 각 게임 카드에 **[방송에 띄우기]** 를 다시 넣었다.
다른 게임이 떠 있으면 **[이 게임으로 바꾸기]**, 그 게임이 떠 있으면 **[방송 중]**.

**팝업도 하나로 합쳤다.** [게임 바꾸기] 전용 팝업과 [게임 관리] 팝업이 따로 있어
같은 일을 두 곳에서 했다. 이제 [게임 바꾸기]·[게임 고르기]·[내 게임]이 모두 같은
팝업을 연다.

## 3. 미리보기가 비는 문제

### 3-1. 재현 시도

이 환경에서는 재현하지 못했다.

- 스튜디오 직접 접속 → 로그인 세션이 없어 실패 (비밀번호는 대신 입력하지 않는다)
- 운영 중인 서버의 데이터를 복사해 **별도 서버를 띄워** 브라우저로 열기
  → 윈도우에서 만든 빌드라 리눅스에서 Prisma 모듈이 로드되지 않아 실패

그래서 원인을 찍는 대신 **원인을 화면이 직접 말하게** 만들었다.

### 3-2. 확실한 결함 — TTS 가 걸리면 후원 알림이 영영 안 뜬다

후원 알림 재생이 `Promise.all([표시 시간, TTS 읽기])` 로 되어 있었다.
**브라우저가 음성을 막으면 speechSynthesis 는 `onend` 를 영영 부르지 않는 경우가
있다**(자동재생 정책, 배경 탭, 목소리 목록 미도착). 미리보기는 iframe 안이라 특히
걸리기 쉽다. 그러면 `busy` 가 true 로 굳고 **그 뒤로는 [테스트 후원 보내기]를 몇 번을
눌러도 화면에 아무것도 안 뜬다.** 오류도 나지 않는다.

**고침.** 읽기에 시간 제한(20초)을 뒀다. 읽기가 끝나지 않아도 다음으로 넘어간다.

### 3-3. 화면이 스스로 원인을 말한다

"미리보기가 비었다" 는 원인이 넷인데 화면상으로는 전부 똑같이 비어 보인다.

1. 실시간 연결이 안 붙었다
2. 붙었는데 서버에 띄운 게임이 없다 / 재생할 후원이 없다
3. 둘 다 정상인데 **틀 크기를 못 재서** 화면을 통째로 감추고 있다 (scale 0)
4. 정상인데 [보여 줄 것]에서 그 층을 꺼 두었다

미리보기 툴바 아래에 한 줄이 뜬다. **정상 재생 중일 때는 뜨지 않는다.**

3번을 알기 위해 오버레이 캔버스가 **틀 크기를 쟀는지**를 부모 창에 보고하도록
새로 만들었다(`donaido-overlay-canvas`). 이 신호가 없으면 "연결은 됐는데 안 나온다" 와
구분할 방법이 없었다.

게임 연결 배지도 좁은 화면에서 숨겨지던 것을 항상 보이게 했다.

## 4. 화면 정리

| 무엇 | 왜 문제였나 | 어떻게 바꿨나 |
|---|---|---|
| **[방송 종료]** | 하는 일은 회차를 끝내고 게임을 내리는 것뿐인데, 이름은 라이브 방송을 끊는 것처럼 읽힌다 | **[게임 내리기]** 로 변경, 툴팁에 "라이브 방송은 그대로입니다" |
| **[유튜브 채팅에 올리기]** | 미연결 크리에이터에게도 보였다. 누르면 오류만 난다 | 연결돼 있을 때만 그린다 (API 가 연결 여부를 함께 응답) |
| **[새 탭에서 보기]** | 진단용 링크. 크리에이터에겐 검은 화면에 배지 하나뿐 | 제거. 진단은 3-3 의 한 줄이 대신한다 |
| **[게임 바꾸기] 전용 팝업** | [게임 관리] 팝업과 같은 일을 두 곳에서 했다 | 하나로 합쳤다 |
| 단축키 안내 문단 | 다섯 줄이라 읽지 않는다 | 두 줄로 축약 |
| 안내 문구 | "위 [게임 바꾸기]에서 합니다" 등 맞지 않는 안내가 남아 있었다 | 현재 구조에 맞게 재작성 |

**남긴 것** — 참여 코드·QR·링크 복사·안내 문구 복사(방송 중 가장 급하게 찾는 것),
"지금 QR 은 휴대폰에서 열리지 않습니다" 경고(참여 주소가 localhost 라 실제로 그렇다),
[방송 화면 보기]·[게임 조작창 열기](서로 다른 일을 한다).

## 5. 검증

### 5-1. 회귀 테스트 — 38개 파일 517건 전부 통과

신규 14건:

- 진행 컨트롤 카드를 화면에 고정하지 않는다
- 전부 정상이면 진단 줄이 아무 말도 하지 않는다
- 틀 크기를 못 재면 그 사실을 알린다
- 게임 연결은 됐는데 띄운 게임이 없으면 그렇게 말한다
- 연결이 안 붙었으면 층별로 따로 알린다
- 두 층을 모두 꺼 두었으면 그것부터 알린다
- 재생 대기가 밀려 있으면 건수를 알린다
- 오버레이 캔버스가 측정 결과를 부모에게 알린다
- [게임 관리] 팝업의 게임 카드에서 바로 띄울 수 있다
- 띄우는 팝업이 하나로 합쳐졌다
- 회차를 끝내는 버튼을 [방송 종료]라고 부르지 않는다
- 유튜브가 연결돼 있을 때만 채팅 공유 버튼을 그린다
- TTS 읽기에 시간 제한을 둔다
- 게임 API 가 유튜브 연결 여부를 내려주고, 해제된 연결은 세지 않는다

### 5-2. 정적 검사

- `tsc --noEmit` — 오류 0
- `eslint` — 오류 0

### 5-3. 손대지 않은 것

후원 결제, MO 번호, EMMA, 정산 계산. 오버레이 배치값의 저장 범위와 변환 방식도 그대로.
