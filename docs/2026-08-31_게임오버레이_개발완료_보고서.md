# 게임 오버레이 개발 완료 보고서

작성일: 2026-08-31
대상: 크리에이터 스튜디오 → 후원·게임 오버레이 (게임 오버레이 탭) / OBS·PRISM 게임 브라우저 소스 / 시청자 참여 페이지
지시 사항: 크레딧 등 금전성 보상 제외, 크리에이터에게 맞는 게임으로 구성, 토네이도 디자인·캐릭터 적용, 운영 편의성 중심 UX

## 0. 요약

- 게임 **8종**을 새로 만들었습니다. 셀러브릭스의 쿠폰·크레딧 구조는 **전부 들어내고**, 보상은 크리에이터가 방송에서 직접 주는 **무형 보상의 이름만 기록**합니다. 결제·정산 원장과는 어떤 컬럼으로도 연결하지 않았습니다.
- 스튜디오 메뉴를 **`후원·게임 오버레이`** 로 바꾸고, 화면 상단에 OBS·PRISM 연결(공통), 그 아래를 **[후원 오버레이] / [게임 오버레이] 2탭**으로 나눴습니다.
- 브라우저 소스는 **토큰 1개 · URL 2개**입니다. 후원 알림과 게임을 OBS 에서 따로 배치·숨김 할 수 있습니다.
- 방송 중 운영을 위해 **진행 버튼에 확인창을 넣지 않고**, 대신 [마감 취소] · [발표 취소] · 5초 실행취소를 붙였습니다. 단축키(Space/Enter/Backspace)와 **팝아웃 컨트롤 창**(OBS 사용자 정의 브라우저 도크에 그대로 넣을 수 있음)도 만들었습니다.
- 셀러브릭스에서 발견한 **정답 노출 결함**(게임 상태 API 가 정답·확률을 그대로 내려보냄)은 옮기지 않았습니다. 공개 응답에서 정답·키워드를 서버가 잘라냅니다.
- 타입 검사 통과, 추첨 로직 회귀 테스트 21건 전부 통과했습니다.

## 1. 적용한 게임 8종

| 게임 | 진행 | 크리에이터에게 맞춘 부분 |
|---|---|---|
| **회오리 룰렛** | 항목 입력 → [돌리기] | 시청자 참여 없이 혼자 바로 돌립니다. 회오리 모티프 원판 |
| **사다리타기** | 출발/도착 입력 → [돌리기] | 번호를 골라 한 줄씩 추적하는 버튼 제공 |
| **순위 추첨** | 참여 열기 → 결과 발표 | 1등부터 순서대로 카드가 올라옵니다. 등수별 보상 지정 |
| **실시간 투표** | 참여 열기 → 결과 발표 | 익명 참여. 다음 곡·다음 컨텐츠를 시청자와 함께 결정 |
| **라이브 퀴즈** | 참여 열기 → 마감 → 발표 | 정답은 발표 전까지 어디에도 나가지 않습니다 |
| **선착순 키워드** | 참여 열기 → 발표 | 대소문자·띄어쓰기를 무시해 억울한 탈락이 없습니다 |
| **숫자 맞히기** | 참여 열기 → 발표 | 가장 가까운 사람 / 정확히 맞힌 사람 두 가지 판정 |
| **후원 목표 게이지** | 시작 → 확정 | **누적 후원 금액**이 실시간으로 차오릅니다. 토네이도 전용 게임 |

**제외한 것**

- **박스깡(확률형 뽑기)** — 유료 참여와 확률 보상이 결합하면 경품·사행성 규제 검토가 필요합니다. 지난 보고서에서 미루자고 말씀드린 그대로 빼 두었습니다.
- **쿠폰 · 크레딧 · 포인트** — 지시하신 대로 전부 제외했습니다. 발행 코드도, 잔액 개념도 없습니다.

## 2. 화면 구조

### 2-1. 메뉴

`방송·오버레이` → **`후원·게임 오버레이`** (`src/app/studio/layout.tsx`)

### 2-2. 페이지

```
[페이지 헤더] 후원·게임 오버레이

■ OBS · PRISM 연결  (탭 밖, 항상 표시)
   · 발급 상태 / 토큰 마스킹 / 현재 연결 수
   · 후원 알림 소스 URL   /overlay/{id}?token=...
   · 게임 소스 URL        /overlay/{id}/game?token=...
   · [URL 발급 / 재발급] · [자세한 등록 방법]

■ 탭  [ 후원 오버레이 ] [ 게임 오버레이 ● ]      ← 게임이 떠 있으면 상태 점 표시

  후원 오버레이 : 기존 내용 그대로 (알림 꾸미기 · 금액 구간 · 테스트 · 전송 내역)
  게임 오버레이 : 진행 컨트롤 · 실시간 현황 · 미리보기 · 내 게임 · 진행 이력
```

- 탭 상태는 주소에 남습니다(`/studio/overlay?tab=game`). 새로고침·뒤로가기·즐겨찾기가 그대로 동작합니다.
- 기존 `/studio/overlay` 주소는 그대로 살아 있습니다(기본 탭 = 후원 오버레이).

### 2-3. 브라우저 소스를 2개로 나눈 이유

게임은 화면 가운데를 크게 쓰고, 후원 알림은 아래쪽에 잠깐 뜹니다. 한 소스로 묶으면 크기·위치를 따로 잡을 수 없고 게임만 잠시 숨기는 것도 안 됩니다. **토큰은 하나**라 크리에이터가 관리할 비밀은 늘지 않고, 재발급하면 둘 다 함께 무효화됩니다.

방송용 동시 연결 상한은 3 → **6**으로 올렸습니다. 소스가 하나 늘었기 때문입니다.

## 3. 크리에이터 운영 UX

### 3-1. 원칙

1. **한 화면에서 끝난다** — 띄우기 → 마감 → 발표까지 페이지 이동이 없습니다.
2. **지금 눌러야 할 버튼 하나만 크게** — 나머지는 약하게 둡니다.
3. **진행 버튼에 확인창을 넣지 않는다** — 방송 중 확인창은 타이밍을 죽입니다.
4. **되돌릴 수 있게 한다** — [마감 취소] · [발표 취소] · 5초 실행취소 토스트.
5. **되돌릴 수 없는 것만 확인창** — 게임 삭제.

### 3-2. 컨트롤 패널

```
[룰렛] 오늘의 벌칙 룰렛           [진행 중]  [128명]  [00:24]   ← 높이 고정(흔들림 없음)
────────────────────────────────────────────────────────────
  [   참여 마감   ]  [ 바로 발표 ]  [ 내리기 ]                ← 주 버튼만 크게
────────────────────────────────────────────────────────────
  실시간 집계                    │  방송 화면 미리보기
  A. 파랑 ████████░░ 62 · 48%    │  (실제 오버레이를 그대로)
  B. 초록 █████░░░░░ 41 · 32%    │  [QR 크게 보기] [링크 복사]
                                  │  [팝아웃 컨트롤] [새 탭]
```

- 상태 배지와 남은 시간 배지는 **폭·높이를 고정**했습니다. 상태가 바뀌어도 아래 내용이 위아래로 흔들리지 않습니다. (지난 미리보기 보고서에서 정한 원칙을 그대로 적용)
- 미리보기는 **1920×1080 으로 그린 뒤 통째로 축소**합니다. 방송 화면과 픽셀 단위로 같습니다.
- 참여자 유입·집계는 SSE 로 흘러오므로 새로고침이 필요 없습니다.

### 3-3. 방송 중 조작 장치

| 장치 | 내용 |
|---|---|
| **단축키** | `Space` / `Enter` = 주 버튼, `Backspace` = 마감·발표 취소, `Esc` = QR 닫기. 입력 칸에 커서가 있을 때는 동작하지 않습니다 |
| **팝아웃 컨트롤** | `/game-control` — 작은 창으로 열립니다. **OBS [보기]→[도크]→[사용자 정의 브라우저 도크]** 에 이 주소를 넣으면 OBS 안에서 진행할 수 있습니다. 팝아웃 창에서도 게임을 새로 띄울 수 있습니다 |
| **QR 크게 보기** | 시청자에게 화면을 보여 줄 때 씁니다 |
| **한 판 더** | 결과 발표 후 같은 게임을 새 회차로 바로 다시 시작합니다 |
| **자동 마감** | 게임마다 30~60초 등으로 설정하면 시간이 되면 자동으로 마감됩니다(별도 스케줄러 없이 처리) |

## 4. 디자인

- **팔레트는 도네이도 브랜드 토큰**을 그대로 씁니다(brand 꿀색 계열 + ink + accent). 셀러브릭스의 허니/벌집 모티프는 쓰지 않았습니다.
- **회오리 모티프**를 일관되게 적용했습니다. 카드 머리의 회오리 마크, 룰렛 중심의 회오리 라인, 목표 게이지의 훑고 지나가는 빛.
- **도네이도 캐릭터**를 장면마다 배치했습니다.

| 장면 | 캐릭터 |
|---|---|
| 참여 모집 중 | 응원 토네이도 (`cheer`) |
| 당첨 발표 | 선물 팡 (`gift-pop`) |
| 투표 결과 | 마이크 댄스 (`mic-dance`) |
| 목표 게이지 진행 중 | 하트 포옹 (`heart-hug`) |
| 목표 달성 | 마이크 댄스 |

- **이모지 없음**, 아이콘은 lucide 라인 아이콘만 사용(절대 규칙 1 준수).
- **안전 영역** — 화면 아래쪽 약 170px(1920 기준)을 비워 유튜브 자막·채팅 UI 와 겹치지 않게 했습니다.
- **QR 은 항상 같은 자리, 같은 크기**(260px)로 그립니다. 시청자가 학습할 수 있어야 하고, 더 작으면 휴대폰이 인식하지 못합니다.
- 게임 전용 모션 7종을 `globals.css` 에 추가했습니다(등장/퇴장/결과 팝/순위 카드/룰렛 대기 회전/게이지 빛/마감 임박).

## 5. 시청자 참여

- 방송 화면의 QR 또는 링크(`/play/{6자리 코드}`)로 들어옵니다. **로그인·앱 설치 없이** 참여합니다.
- 닉네임은 **후원 메시지와 같은 필터**를 통과합니다. 전화번호·계좌·링크는 자동 마스킹되고 금칙어는 차단됩니다.
- **중복 참여 차단**은 브라우저가 만든 기기 식별값 + 회차 단위 유니크 제약(DB)입니다. IP 로 묶지 않았습니다 — 이동통신망 NAT 때문에 서로 다른 시청자가 한 사람으로 취급되어 정상 참여가 막힙니다. 남용은 IP 속도 제한(분당 30건)으로 잘라냅니다.
- **참여 후에는 결과를 조회하지 않습니다.** 결과는 방송 화면에서 발표됩니다. 시청자 수천 명이 각자 결과를 폴링하면 참여 API 보다 결과 조회가 서버를 먼저 무너뜨립니다.

## 6. 후원과의 연결

| 기능 | 동작 |
|---|---|
| **후원 목표 게이지** | 회차를 연 시각 이후의 결제 완료 후원 금액을 합산합니다. 환불·테스트 후원은 제외됩니다 |
| **후원 자동 참여** | 게임이 열려 있는 동안 후원하면 자동으로 참여자에 올라갑니다. **순위 추첨에서만** 동작합니다 — 퀴즈·투표·키워드·숫자는 무엇을 골랐는지 알 수 없어 후원만으로 참여시킬 수 없습니다 |
| **참여 방식 3종** | 링크·QR / 후원 자동 참여 / 둘 다. **[후원 자동 참여]만 고르면 무료 참여 경로가 없다는 경고**를 화면에 띄웁니다 |

> 후원 송출(`dispatchBroadcast`) 뒤에 게임 참여를 시도하지만, **게임 쪽 실패는 서비스 내부에서 전부 삼킵니다.** 후원 처리·결제·정산에는 어떤 경우에도 영향을 주지 않습니다.

## 7. 공정성과 보안

| 항목 | 처리 |
|---|---|
| **정답 노출 차단** | 게임 상태를 세 갈래로 나눠 내보냅니다. 오버레이·참여 페이지에는 정답·키워드를 제거한 값만, 크리에이터 컨트롤에만 전체. 발표(RESULT) 후에 비로소 정답이 공개됩니다 |
| **추첨 난수** | `Math.random` 을 쓰지 않고 CSPRNG(`node:crypto` randomInt)만 씁니다 |
| **결과 확정 주체** | 항상 서버입니다. 클라이언트가 보낸 당첨자를 받지 않습니다 |
| **진행 중 설정 잠금** | 회차가 열려 있는 동안에는 게임 설정을 수정할 수 없습니다 |
| **이력 보존** | 회차를 리셋해도 참여자·당첨자를 지우지 않습니다. 회차(seq)별로 남습니다 (셀러브릭스는 리셋 시 참여자를 삭제해 이력이 사라집니다) |
| **선착순 공정성** | 키워드 게임은 들어온 순서를 섞지 않고 그대로 자릅니다. 한 번 참여하면 입력을 바꿀 수 없습니다 |
| **개인정보** | 참여 닉네임에 금칙어·개인정보 필터를 적용합니다 |

## 9. DB 변경

새 표 4개입니다. 결제·정산 표와는 어떤 외래키로도 연결되지 않습니다.

| 표 | 용도 |
|---|---|
| `game` | 게임 정의(재사용). 종류·제목·항목·설정·참여 방식·자동 마감 |
| `game_round` | 회차. 상태(OPEN/CLOSED/RESULT/ENDED), 참여 코드, 결과 |
| `game_participant` | 참여자. 회차 단위 유니크 제약으로 중복 참여 차단 |
| `game_winner` | 당첨자. 보상 이름과 전달 완료 체크 |

**적용 방법**

```bash
# 개발 DB
npm run db:migrate

# 초기화 + 시드 (예시 게임 4개가 함께 들어갑니다)
npm run db:reset

# 내장 DB 미리보기
npm run preview        # 포트 3025
```

| 추첨 로직 회귀 테스트 21건 | **전부 통과** |

테스트에서 확인한 것

- 룰렛이 2,000회 추첨에서 특정 칸으로 쏠리지 않음
- 사다리 도착 보상이 **중복 없이 일대일**로 배정됨 (같은 보상이 두 사람에게 가지 않음)
- 키워드 선착순이 **섞이지 않고 들어온 순서 그대로** 잘림
- 숫자 맞히기에서 차이가 같으면 **먼저 낸 사람이 우선**
- 퀴즈 정답자 수 집계와 정답자 중 1명 추첨
- 투표에서 범위를 벗어난 입력은 집계에서 제외, 무투표 시 1위를 만들지 않음
- 순위 추첨이 참여자 수보다 많이 뽑지 않고 같은 사람을 두 번 뽑지 않음

`tests/game-result.test.ts` 로 커밋해 두었으니 `npm test` 에 함께 돌아갑니다.

## 11. 확인 부탁드리는 것 / 남은 것

1. **실행 확인** — `npm run db:reset` 후 `npm run preview` 로 띄우고, 크리에이터 계정(creator1@tornado.kr / tornado1234!)으로 [후원·게임 오버레이] → [게임 오버레이] 탭에서 예시 게임을 띄워 봐 주세요. 브라우저 두 개로 참여 페이지까지 함께 열면 전체 흐름이 보입니다.
2. **메뉴 라벨** — `후원·게임 오버레이` 로 넣었습니다. `후원, 게임 오버레이` 로 바꾸길 원하시면 한 줄이면 됩니다.
3. **관리자(`/admin`) 게임 관리 화면**은 이번 범위에 넣지 않았습니다. 신고·강제 종료·통계가 필요하면 다음에 붙이겠습니다.
4. **캐릭터 신규 에셋** — 지금은 기존 5종을 배치해 재사용했습니다. 룰렛 회전 중, 두구두구, 폭죽 축하 같은 전용 컷을 만들면 연출이 확실히 좋아집니다.
5. **부하 시험** — 시청자 수천 명 동시 참여는 실제 트래픽으로 확인해야 합니다. 현재는 IP 분당 30건 제한 + 회차 유니크 제약 + 상태 발행 0.7초 묶음 처리로 설계해 두었습니다.
6. **박스깡(확률형)** — 법률 검토가 끝나면 추가하겠습니다. 지금은 목록에 없습니다.
