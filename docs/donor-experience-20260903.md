# 도네이도 후원자 중심 후원 페이지 개편

## 적용 결과

- 참고 구조: https://ongigive.co.kr/donate/a0000232 (나눔플러스).
- PC: 가운데 700px 본문 + 오른쪽 104px 세로 메뉴. 크림색 바탕, 둥근 흰 패널, 겹쳐 배치한 크리에이터 프로필 카드.
- 오른쪽 메뉴: 후원자 로그인/내 프로필, 후원하기, 내 문자후원, 마이페이지, 문의, 도네이도 홈.
- 긴 화면에서도 메뉴가 유지된다. 낮은 화면에서는 메뉴 내부 스크롤로 모든 항목에 접근할 수 있다.
- 모바일: 로그인 버튼과 4열 후원자 메뉴. 기존 문자후원 하단 버튼 및 결제 흐름 유지.
- 상단 배너: 본문 폭에 맞는 라운드 영역, 1774×887 원본 비율 정보, 반응형 크롭, 우선 로드.
- 기존에 생성한 도네이도 캐릭터 좌우 WebP 이미지를 재사용. 새로 외부 사이트 이미지를 가져오지 않았다.
- 이미지 사각 경계는 종횡비를 맞춘 마스크로 부드럽게 처리. 장식은 고정되며 클릭·포커스를 방해하지 않는다.

## 후원자 화면

- 후원 페이지: `/c/TOR-8K2M`
- 후원자 로그인: `/c/TOR-8K2M/login`
- 내 문자후원: `/c/TOR-8K2M/messages`
- 기존 마이페이지 `/my`의 환불·거래 상세 기능은 유지하고 답글 표시만 추가했다.
- 비로그인 사용자는 후원자 로그인 화면으로 이동한다. 로그인 후 원래 내역으로 복귀한다.
- 본인 계정에 연결된 DonorProfile의 MO 내역만 표시한다. 다른 크리에이터와 WEB 후원은 이 문자내역 목록에 섞지 않는다.
- 소셜 로그인은 전화번호 인증이 아니다. 휴대폰 연결 전에는 내역을 노출하지 않고 기존 본인인증 화면으로 안내한다.
- 내역은 20건 단위 페이지 나눔. 암호화 원문·전화번호 전체는 화면 데이터에 포함하지 않는다.

## 크리에이터 답글

- 크리에이터 관리자 → 후원 내역 → 해당 후원 상세에서 작성·수정.
- 한 후원당 답글 1개, 최대 1,000자. 해당 후원자와 크리에이터만 열람.
- 활성화된 승인 크리에이터의 소유권을 서버에서 확인. 다른 크리에이터, 후원자, 정지 계정은 작성 불가.
- 답글은 일반 텍스트로 표시한다. HTML을 실행하지 않는다.
- 답글은 후원자 내 문자후원 및 마이페이지에 표시된다. 자동 MT 발송, 방송 송출, 결제, 정산 변경은 하지 않는다.

## 카카오·네이버 로그인

- 기존 준비용 어댑터를 공식 OAuth 인가 코드 방식으로 구현했다.
- 공급자 고유 ID로만 로그인한다. 이메일이 같아도 기존 이메일/관리자 계정으로 자동 연결하지 않는다.
- 신규 사용자는 필수 약관 동의 후 DONOR 계정으로 생성한다. DB의 기존 50종 랜덤 캐릭터 배정 규칙을 그대로 사용한다.
- state 대조 및 소모, 외부 복귀 URL 차단, 10분 만료 암호화·서명 임시 쿠키, 속도 제한 적용.
- 공급자 액세스 토큰은 프로필 조회에만 사용하고 DB·로그에 보관하지 않는다. 공급자 사진으로 캐릭터를 덮어쓰지 않는다.
- 실제 키가 없으면 준비 중으로 표시하며 임의의 인증 성공을 만들지 않는다.
- 현재 KAKAO_CLIENT_ID, NAVER_CLIENT_ID, NAVER_CLIENT_SECRET 미설정. 실제 공급자 계정 로그인은 아직 실검증하지 않았다.
- 운영 준비: 앱 등록 및 검수, 서비스 도메인, KAKAO_CLIENT_ID/필요 시 KAKAO_CLIENT_SECRET, NAVER_CLIENT_ID/SECRET, 각 REDIRECT_URI를 설정한다. 콜백 경로는 `/api/auth/social/kakao/callback`, `/api/auth/social/naver/callback`.
- 약관·개인정보 처리방침의 실제 수집 항목 및 보유기간도 소셜 가입에 맞춰 운영 검토가 필요하다. 현재 시드 약관은 샘플 문안이다.
- 공식 문서: [카카오 REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api), [네이버 로그인 API](https://developers.naver.com/docs/login/api/api.md).

## 테스트 후원자

- 후원자 로그인 화면에서 ‘테스트 후원자로 바로 로그인’.
- APP_ENV=local에서만 화면 표시 및 서버 실행 허용. 운영에서는 사용할 수 없다.
- `donor@tornado.kr` 기존 계정의 비밀번호·상태·캐릭터는 보존한다. 없는 계정만 생성한다.
- 테스트 번호가 다른 계정에 연결돼 있으면 덮어쓰지 않고 중단한다.
- 바람소리(TOR-8K2M) 우선으로 검수용 MO 내역 3건과 답글 1건을 멱등 생성한다.
- 샘플은 isTest=true, PAYMENT_FAILED, 송출/MT SKIPPED. 실제 결제·문자·정산 원장을 만들지 않는다. 화면에 테스트임을 표시한다.
- 수동 보충 명령: `node node_modules/tsx/dist/cli.mjs scripts/seed-donor-preview.ts` (실행 대상 DATABASE_URL 확인, 로컬 전용).

- 추가 마이그레이션: `20260903150000_donor_social_and_replies`.
- 신규 테이블: social_identity, donation_reply. 기존 거래 테이블 데이터 삭제 없음.

- Claude의 SNS 링크, 후원 설정, MO/MT, 관리자 등의 기존 수정사항은 보존. 이번 작업은 후원자 셸/화면/답글/로그인 경로에 한정했다.
- 커밋·푸시하지 않았다.

## 검증

- TypeScript 및 변경 범위 ESLint 통과.
- 프로덕션 빌드 통과, localhost:3025 재시작 완료.
- 전체 회귀 테스트: 27개 파일 / 323개 테스트 통과.
- 실제 Edge 브라우저 검수: 35개 항목 통과, 런타임 오류 0건.
- PC 1440/1280/1024px, 모바일·태블릿 768/390/320px에서 가로 넘침·메뉴 표시·스크롤 고정 확인.
- 모든 프로필·배너 이미지 로드 확인, 좌우 WebP HTTP 200.
- 비로그인 접근 제한 → 테스트 후원자 로그인 → 내역 표시 → 테스트 크리에이터의 검수용 답글 수정 → 후원자에게 표시 → 원래 검수용 답글 복원까지 확인.
- 실제 결제나 MT 발송을 시험하지 않았다. OAuth 네트워크 응답은 mock 테스트로 검증했고 실사업자 인증은 위 설정 후 별도 검증해야 한다.
- 테스트는 `tools/test.mjs`가 생성한 독립 메모리 DB에서 실행. 기존 미리보기 DB에 TRUNCATE하지 않았다.
- 서버 빌드/실행 시 기존 Redis 연결 경고가 있었다. 로컬 인메모리 폴백에서 이번 기능은 정상 동작했다. 운영의 Redis 가용성/방송 송출 검증을 대체하지 않는다.
- 재실행: `npm test`, `node e2e/donor-experience-e2e.mjs` (후자는 로컬 3025 + 설치된 Edge).
- QA 이미지: `tmp/donor-experience-qa/donation-1440.png`, `donation-390.png`, `donor-login.png`, `donor-messages.png`. tmp는 버전관리 제외.
- 생성 이미지 경로·원본 프롬프트·내장 image_gen 사용 기록은 `donation-margin-background-20260903.md`, `creator-banner-refresh-20260903.md` 참고.
