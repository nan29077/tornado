# 게임 오버레이 — 지적사항 수정 및 검증 보고서

작성일: 2026-09-01
대상: 전체 점검 보고서에서 나온 결함 2건 · 개선점 3건
검증 방식: 실제 구동 중인 서버(localhost:3025)에 직접 요청을 넣어 시나리오별 확인

---

## 0. 결론

**5건 모두 수정했고, 4건은 실제 서버로 재현해 통과를 확인했습니다.** 나머지 1건(연결 상한 등록)은 코드·구문·런타임 동작까지는 확인했지만 "상한 초과 시 오래된 연결이 끊기는 장면"을 직접 재현하지는 못했습니다. 이유는 아래 4장에 적었습니다.

기존 기능이 깨지지 않았는지도 함께 확인했습니다. **화면 22개 전부 정상(200)**, 후원 알림 스트림도 그대로 동작합니다.

## 1. 수정 내역

| # | 내용 | 고친 파일 |
|---|---|---|
| 1 | 게임 오버레이 SSE 를 후원 알림과 **같은 동시 연결 카운터에 등록** | `game-stream.ts`, 게임 SSE 라우트 2개 |
| 2 | **마감 취소 시 자동 마감 타이머 복구** | `games.ts` (`reopenRound`) |
| 3 | 사다리 결과가 나온 뒤에도 **번호를 바꿔 따라가기** | `games.ts`(`traceLadder`), 진행 조작 라우트, 컨트롤 화면 |
| 4 | 죽은 코드 `nextAction()` 제거 | `game-catalog.ts` |
| 5 | (보완) 참여 주소가 이 PC 안에서만 통하면 **컨트롤 화면에 경고** | `game-studio.tsx` |

### 지난 보고 정정

지난 보고서에서 `ROUND_STATUSES` 도 죽은 코드라고 적었는데 **틀렸습니다.** 이 상수는 `RoundStatus` 타입의 출처이고 그 타입이 8곳에서 쓰입니다. 실제로 죽어 있던 것은 `nextAction()` 하나뿐이라 그것만 지웠습니다.

### 3번을 "문구 수정"이 아니라 기능으로 고친 이유

사다리는 [돌리기] 시점에 결과가 확정되면서 번호 버튼이 사라져, 한 회차에 한 줄만 볼 수 있었습니다. 문구만 고칠 수도 있었지만, 방송에서 "가님은 여기, 나님은 여기" 하고 한 줄씩 짚어 주는 게 사다리의 재미라 **결과 확정 후에도 따라갈 줄만 바꿀 수 있게** 만들었습니다.

핵심은 **결과를 다시 뽑지 않는다**는 것입니다. `traceLadder` 는 이미 저장된 결과에서 `activeIndex`(굵게 그릴 줄) 하나만 바꿉니다. 사다리 배치도 당첨 결과도 건드리지 않아 조작 여지가 없습니다. 아래 3장에서 실제로 확인했습니다.

## 2. 수정 검증 — 실제 서버 시나리오

### 2-1. 마감 취소 후 자동 마감 복구 (결함 2)

실시간 투표(자동 마감 60초)로 확인했습니다.

| 단계 | 상태 | 자동 마감 |
|---|---|---|
| 시작 | OPEN | **59초 남음** |
| 참여 마감 | CLOSED | 없음 |
| 마감 취소 | OPEN | **60초 남음 (복구)** |

**통과.** 예전에는 마감을 취소하면 그 회차는 남은 시간 표시도 자동 마감도 없이 계속 열려 있었습니다.

### 2-2. 사다리 따라가기 (개선점 4)

| 확인 | 결과 |
|---|---|
| 결과 나오기 전에 따라가기 시도 | 거절 — "아직 결과가 나오지 않았습니다" |
| [돌리기] 1번으로 시작 | activeIndex 0, 결과 `가→2등 / 나→꽝 / 다→1등` |
| 3번으로 바꿔 따라가기 | activeIndex 2 |
| **사다리 배치·당첨 결과 비교** | **완전히 동일** (rungs · rows · order · destinations · starts 전부 일치) |
| 없는 번호(9) 지정 | 거절 — "없는 번호입니다" |

**통과.** 다시 뽑히지 않는다는 것을 결과 전체를 비교해 확인했습니다.

### 2-3. 참여 주소 경고 (보완 5)

참여 주소가 `localhost` · `127.0.0.1` 이면 컨트롤 화면에 경고가 뜹니다. 방송 중에 열리지도 않는 QR 을 띄우는 사고를 막습니다.

### 2-4. 연결 상한 등록 (결함 1)

코드상 게임 SSE 도 후원 알림과 같은 `registerOverlayConnection()` 에 등록되고, 방송용(토큰)/미리보기(세션)를 구분해 셉니다. 등록을 넣은 뒤에도 **게임 SSE 가 정상 동작하는 것은 확인**했습니다(아래 2-5의 오버레이 상태 수신이 이 경로를 탑니다).

다만 **"상한을 넘겨 오래된 연결이 끊기는 장면"은 재현하지 못했습니다.** 브라우저에서 연결 9개를 동시에 열어 두면 스크립트 실행기가 반환되지 못하고 시간 초과됩니다(열린 스트림 때문에 페이지가 유휴 상태가 되지 않음). 로컬 워크스페이스가 살아나면 서버 로그로 바로 확인할 수 있습니다.

## 3. 기능 전반 시뮬레이션 (회귀 확인)

### 3-1. 실시간 투표

| 항목 | 결과 |
|---|---|
| 서로 다른 기기 3대 투표 | 집계 `[1, 2, 0, 0]`, 참여자 3명 |
| 같은 기기 재참여 | 차단 — "이미 참여하셨습니다" |
| 범위 밖 선택지(9) | 차단 — "선택지를 골라 주세요" |
| 잘못된 기기키 | 차단 — "참여 정보를 확인할 수 없습니다" |
| 결과 발표 | 1위 "노래" (2표) |

### 3-2. 라이브 퀴즈 (정답 유출 차단이 핵심)

| 항목 | 결과 |
|---|---|
| 시청자 참여 페이지 응답 | 문제·선택지는 있고 **정답 필드 없음** |
| 방송 오버레이 공개 상태의 키 목록 | `secret` · `recentParticipants` · `entryMode` · `autoCloseSec` **모두 없음** |
| 발표 전 `result` | `null` |
| 정답 참여 2명 / 오답 1명 | 정답 여부 판정 정확 |
| 닉네임 없이 참여 | 차단 — "닉네임을 입력해 주세요" |
| 마감 후 참여 | 차단 — "지금은 참여를 받지 않습니다" |
| 결과 발표 후 | 정답 0번("노랑") 공개, 정답자 2명, 그중 1명 추첨 당첨 |

정답이 발표 전에는 어느 경로로도 나가지 않는다는 것을 **응답의 키 목록 자체로** 확인했습니다.

### 3-3. 화면 전수 확인

공개 8개 + 스튜디오 11개 + 오버레이 3개, **총 22개 화면 모두 정상(200)**.

```
공개 메인 · 이용방법 · FAQ · 공지 · 고객센터 · 약관 · 개인정보 · 로그인
스튜디오 대시보드 · 후원 내역 · 문자 관리 · 유튜브 연결 · 후원 설정
금칙어·차단 · 신고 · 정산 관리 · 프로필 설정
후원·게임 오버레이(후원탭 / 게임탭) · 팝아웃 컨트롤
게임 오버레이 미리보기 · 후원 오버레이 미리보기
```

### 3-4. 후원 알림 경로 회귀

게임 SSE 가 같은 연결 카운터를 공유하게 됐으므로 후원 쪽을 따로 확인했습니다. 후원 알림 스트림은 그대로 `event: ready` 를 정상 응답합니다.

## 4. 이번에 확인하지 못한 것

| 항목 | 사유 |
|---|---|
| 전체 `tsc --noEmit` | 로컬 워크스페이스(리눅스 VM)가 내려가 실행 불가. **구문은 TypeScript 파서로 파일별 검사(오류 0)**, 동작은 위 시뮬레이션으로 확인 |
| 연결 상한 초과 시 방출 재현 | 4장 2-4 참고 |
| 실제 OBS·PRISM 등록 | 브라우저 소스로는 아직 미확인 |
| 휴대폰 실기기 QR 참여 | `APP_BASE_URL` 이 localhost 라 불가 (보완 5의 경고가 이 상황을 알려 줍니다) |
| 수천 명 동시 참여 부하 | 미실시 |

**부탁드릴 것 하나** — 편하실 때 `npm run typecheck` 와 `npm test` 를 한 번 돌려봐 주세요. 결과가 이상하면 알려 주시면 바로 잡겠습니다.

## 5. 남은 상태
