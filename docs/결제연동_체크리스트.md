# 결제연동 체크리스트

각 결제수단을 실결제 전까지 완료해야 하는 단계 목록입니다.
체크박스는 완료 시 `[x]`로 변경하세요.

---

## 공통 (모든 결제수단 공통)

- [ ] `PAYMENT_PROVIDER` 를 실제 provider 로 변경 (현재 기본값: `mock`)
- [ ] `SAFE_MODE=false` 설정 — 비어 있으면 mock 어댑터가 대신 동작해 가짜 승인이 기록됨
- [ ] `PAYMENT_PIN_CALLBACK_SECRET` 설정 (운영에서 비어 있으면 기동 중단)
- [ ] `PAYMENT_PIN_ALLOWED_IPS` 설정 — PIN 콜백을 받을 결제사 서버 IP 목록
- [ ] `PAYMENT_PIN_SUCCESS_CODES` 에서 `MOCK` 코드 제거 후 결제사 규격 코드로 교체
- [ ] `APP_BASE_URL` 이 `https://` 로 시작하는지 확인 (운영 필수)
- [ ] `APP_ENV=prod` 또는 `staging` 으로 설정
- [ ] `assertProductionSafety()` 통과 확인 (`npm run check:db` 후 `npm run build` 로 확인 가능)

## 헥토파이낸셜 내통장결제 (EzAuth)

**환경변수**

- [ ] `PAYMENT_PROVIDER=hecto`
- [ ] `HECTO_MID` — 헥토 상점아이디 (mercntId, 계약 시 발급)
- [ ] `HECTO_LICENSE_KEY` — 라이선스 키 (계약 시 발급)
- [ ] `HECTO_AES_KEY` — custCi/trPrice 암호화용 AES-256 키 (32바이트)
- [ ] `HECTO_HASH_KEY` — 위변조 검증 해시키 (SHA256 signature 재료)
- [ ] `HECTO_AUTH_UI_BASE` — 결제창 호스트 (기본값 `https://ezauth.settlebank.co.kr`)
- [ ] `HECTO_AUTH_API_BASE` — 서버 API 호스트 (기본값 `https://ezauthapi.settlebank.co.kr:8081`)
  - 주의: UI 호스트와 API 호스트가 같으면 기동이 중단됨
- [ ] `HECTO_CALLBACK_URL` — 헥토 대시보드에 등록할 자사 콜백 URL

**코드 수정 필요 (규격서 수령 후)**

- [ ] `HECTO_SPEC.pinAuthPath` 실제 경로로 교체 (현재 추정값 `/v3/APIPayAuth.do`)
- [ ] `requestPinLink()` 내 TODO 블록을 실 API 호출로 교체 (`hecto.ts` 참고)
  - 요청 필드·응답 필드명 규격서 확인 후 채울 것
  - 완료 후 `mock: false` 로 변경
- [ ] `bootWarnings()` 의 헥토 mock 경고가 뜨지 않는지 확인

**연동 테스트**

- [ ] 헥토 개발 서버에서 계좌 등록 전체 흐름 (등록 → 복귀 → completeRegistration) 확인
- [ ] PIN 인증창 발급 → 후원자 PIN 입력 → `/api/webhooks/pin-callback` 수신 → 승인 흐름 확인
- [ ] 동일 orderNo 재요청 시 멱등 동작 확인 (헥토가 기존 결과를 돌려줘야 함)

## 온기(Ongi) 정기결제

**환경변수**

- [ ] `PAYMENT_PROVIDER=ongi`
- [ ] `ONGI_API_KEY` — 모든 요청 헤더 `X-API-KEY`
- [ ] `ONGI_API_MID` — 선택. 가맹점 식별 강화용 `X-API-MID`
- [ ] `ONGI_RECURRING_MID` — 정기결제 MID (일반 MID 와 다른 경우)
- [ ] `ONGI_WEBHOOK_SECRET` — 웹훅 서명 검증용 공유 비밀 (비어 있으면 fail-closed)
- [ ] `ONGI_API_BASE` — 기본값 `https://api.ongi.site`. 개발 환경이 다르면 변경

**코드 수정 필요 (온기 규격서/경로 수령 후)**

- [ ] `ONGI_SPEC.paymentCreatePath` 채우기 — 결제 생성/URL 발급 경로
- [ ] `ONGI_SPEC.paymentInquirePath` 채우기 — 결제 단건 조회 경로
- [ ] `ONGI_SPEC.paymentCancelPath` 채우기 — 결제 취소 경로
- [ ] `/api/webhooks/ongi/route.ts` 구현 (현재 501 반환 중)
  - 웹훅 URL 온기 대시보드에 등록: `{APP_BASE_URL}/api/webhooks/ongi`
  - 서명 검증 방식 확인 (헤더명, HMAC 알고리즘)
  - 응답 바디 JSON 필드명 확인
- [ ] `ONGI_SPEC.successCode` 확인 (현재 `'0000'` 가정)

**온기 측 확인 사항** (온기.ts 주석 참고)

- [ ] 정기결제 구조 확인: 빌키 방식인가, 결제 URL 발급 방식인가?
- [ ] 등록 복귀 URL 에 어떤 파라미터가 전달되는지 확인
- [ ] 웹훅 서명 헤더명 확인 (현재 `x-ongi-signature` 가정)
- [ ] 서명 알고리즘 확인: `sha256=HMAC-SHA256(secret, "{timestamp}.{rawBody}")` 맞는지

## 카카오페이 정기결제(빌키)

**환경변수**

- [ ] `PAYMENT_PROVIDER=kakao`
- [ ] `KAKAO_SECRET_KEY` — 카카오페이 어드민 키. 소셜 로그인의 `KAKAO_CLIENT_SECRET` 과 다름
- [ ] `KAKAO_CID` — 정기결제 전용 CID. 일반 결제 CID 와 다르므로 계약 시 별도 발급

**연동 흐름 확인**

- [ ] 카카오페이 정기결제는 PIN 단계 없음. `PIN_NOT_SUPPORTED` → `executePayment` 흐름 동작 확인
  - `ALLOW_LEGACY_CONFIRM_LINK=false` (기본값)이면 "카드 결제 준비 중" 안내 반환
  - 카카오 빌키 방식은 `approve()` 직접 호출 경로가 별도로 필요하면 구현 추가 필요
- [ ] 빌키 발급 흐름: `createRegistrationSession` → 카카오 앱 → `pg_token` 복귀 → `completeRegistration`
- [ ] `partner_order_id` 와 `partner_user_id` 가 `registration.id` 와 일치하는지 확인
- [ ] 카카오 빌키 승인 API 경로 확인: `POST https://open-api.kakaopay.com/online/v1/payment/subscription`

**테스트**

- [ ] 카카오페이 개발 환경에서 전체 등록 흐름 확인
- [ ] 빌키로 정기결제 승인(`approve`) 실행 확인
- [ ] `sid` (빌키) DB 저장 확인 (`PaymentMethodToken.billKey`)

## 코엠페이먼츠 카드 빌키 (DIRECTPAY)

**환경변수**

- [ ] `PAYMENT_PROVIDER=koem`
- [ ] `KOEM_MID` — 상점ID (Fix 15자리)
- [ ] `KOEM_API_KEY` — 64자리 고유 암호키 (HMAC-SHA256 서명 키)
- [ ] `KOEM_API_BASE` — 개발기: `https://183.111.29.87:39500` / 상용기: `https://paycc.coam.co.kr`

**코드 확인**

- [ ] 코엠 카드 등록 UI 흐름 별도 구현 여부 확인 (코엠은 호스팅 결제창 없이 카드번호를 직접 받음)
- [ ] `PIN_NOT_SUPPORTED` 처리: 코엠은 PIN 없이 바로 approve() 호출 필요
  - 현재는 `ALLOW_LEGACY_CONFIRM_LINK` fallback 또는 "카드 결제 준비 중" 안내 반환
- [ ] 개발기 IP 호스트 TLS 인증서 이슈 → `NODE_EXTRA_CA_CERTS` 로 사설 CA 등록 (인증서 검증 비활성화 금지)

**테스트**

- [ ] 코엠 개발기에서 카드 빌키 발급 확인
- [ ] 빌키로 승인(`approve`) 및 취소(`cancel`) 확인
- [ ] HMAC-SHA256 서명 검증 통과 확인
