## 2. A — 높음 2건

### A-1. 게임을 띄우면 화면에 떴다 사라졌다 다시 뜬다

**증상.** [방송에 시작]을 누르면 게임이 잠깐 나타났다가 사라지고, 2초쯤 뒤에 다시 나타납니다.

**원인.** 스튜디오 상태를 1.5초 동안 캐시해 둡니다. 게임을 띄운 **직후에도 그 캐시를 지우지 않아서**, 시작 직후 화면이 물어보면 "띄운 게임 없음" 이라는 **직전의 답**이 그대로 돌아왔습니다.

```
t=0.0  [방송에 시작]  → 서버는 회차를 만든다
t=0.2  화면이 상태를 묻는다 → 캐시에 남은 "게임 없음" 이 돌아온다 → 화면이 비워진다
t=2.0  캐시가 만료된다 → 그제서야 게임이 다시 나타난다
```

**고침.** 게임을 띄우거나 내리는 순간 그 결과를 **캐시에 곧바로 심습니다**(`primeStudioStateCache`). 지우는 게 아니라 심는 이유는, 지우기만 하면 바로 뒤따라오는 요청이 DB 를 다시 훑어 같은 순간에 여러 번 조회가 몰리기 때문입니다.

같이 잠근 것 — 회차 시작을 **크리에이터 단위 자문 잠금**으로 줄 세웠습니다. 예전에는 스튜디오 창과 팝아웃 컨트롤에서 거의 동시에 시작하면 OPEN 회차가 두 개 만들어져, 하나는 화면에 안 보이는 채로 참여를 계속 받았습니다.

### A-2. SNS 링크에 `javascript:` 주소가 저장됐습니다

**원인.** 주소 검사가 **문자열에 `youtube.com` 이 들어 있는지**만 봤습니다.

```js
new URL('javascript://www.youtube.com/%0Aalert(1)').hostname
// → 'www.youtube.com'   ← 호스트 검사를 그대로 통과합니다
```

저장된 값은 후원 페이지의 링크(`<a href>`)로 그대로 나갑니다. 즉 **크리에이터가 자기 후원 페이지를 보는 팬에게 스크립트를 실행시킬 수 있는** 자리였습니다. `data:` `ftp:` 도 같은 길로 통과했습니다.

**고침.** 호스트를 보기 **전에 스킴부터 잠갔습니다**(http·https 만). 호스트도 끝자리까지 정확히 비교하므로 `www.youtube.com.evil.kr` 은 이제 막힙니다.

## 5. 작업 중 새로 발견한 것 2건

이 둘은 검수 목록에 없었는데, **회귀 테스트가 빨간불로 잡아냈습니다.**

### 5-1. 로그의 카드번호 마스킹이 주문번호까지 지우고 있었습니다

카드번호를 가리려고 **13~16자리 연속 숫자**를 전부 `**********3456` 으로 바꾸고 있었습니다. 그런데 이 앱의 주문번호가 14자리입니다.

```
주문번호 20260902123456  →  주문번호 **********3456
```

결제 장애를 추적할 때 **로그로 어느 건인지 특정할 수 없게** 됩니다.

**고침.** 카드번호는 반드시 룬(Luhn) 검사를 통과합니다. 그 검사를 붙여 **진짜 카드번호만** 가립니다. 실제 카드번호(`4111…`)는 여전히 끝 4자리만 남고, 주문번호·금액은 그대로 읽힙니다.

### 5-2. 카카오페이 어댑터 테스트가 항상 실패하고 있었습니다

앱 코드가 아니라 **테스트 쪽 문제**였습니다. `vi.resetModules()` 뒤의 동적 import 는 모듈을 새로 만드는데, 검사에 쓰는 오류 클래스는 옛 모듈의 것이라 `instanceof` 가 맞지 않았습니다. 오류는 정상적으로 던져지는데 검사만 실패하던 상태입니다. 같은 모듈에서 클래스를 가져오도록 고쳤습니다.

## 6. 오늘 요청하신 UI 2건

### 6-1. 게임 관리 — 펼치기 대신 **버튼 + 팝업**

말씀이 맞습니다. 펼치는 방식(`<details>`)은 이 열에 내용이 그대로 쌓여서

- 위쪽 **진행 컨트롤과 미리보기가 화면 밖으로 밀려 올라가고**
- 좁은 열이라 게임 카드가 눌려 **제목이 잘리고 버튼이 두 줄로 접혔습니다**

**바꾼 것.** 그 자리에는 **버튼 세 개만** 둡니다.

```
┌─────────────────────────────────────────────┐
│  🎮  게임 관리                               │
│      게임을 만들고 고치는 곳입니다.           │
│      방송에 띄우기는 위 [게임 바꾸기]에서.     │
│                                             │
│  [+ 새 게임 만들기] [내 게임 3개] [지난 결과]  │
└─────────────────────────────────────────────┘
```

누르면 **넓은 팝업**(최대 900px)이 뜨고, 그 안에서 탭으로 나눠 씁니다.

| 탭 | 하는 일 |
|---|---|
| 내 게임 | 만들기 · 수정 · 삭제 · 미리보기 |
| 지난 게임 결과 | 진행 기록 · 당첨자 · 보상 전달 체크 |

- [+ 새 게임 만들기] 는 팝업을 열면서 **바로 입력 폼까지 펼칩니다.** 두 번 누르지 않습니다.
- 팝업이 넓어서 게임 카드가 **2단으로 여유 있게** 들어갑니다. 제목이 잘리지 않습니다.
- **작성 중일 때는 바깥을 눌러도 닫히지 않습니다.** 실수로 다 날아가지 않게 했습니다. (닫기는 X 로)
- 닫으면 작성 중이던 내용과 열어 둔 미리보기를 함께 정리합니다. 다음에 열었을 때 옛 입력이 남아 헷갈리지 않게요.

띄우는 일은 그대로 [게임 바꾸기](진행 중) · [게임 고르기](대기 중) 팝업 한 곳에 있습니다.

### 6-2. [새 게임 만들기] 버튼이 두 줄로 접히던 것

**원인은 이 버튼 하나가 아니라 버튼 공통 스타일이었습니다.** 줄바꿈을 막는 설정이 없어서, 자리가 좁으면 **어떤 버튼이든** 글자가 두 줄로 접혔습니다.

공통 스타일에 `줄바꿈 없음`을 넣었습니다. 자리가 모자라면 글자가 접히는 게 아니라 **버튼 자체가 아랫줄로 내려갑니다.** 스튜디오 전체의 버튼이 함께 정리됩니다.

버튼에 `+` 아이콘도 붙여 "만들기" 임이 한눈에 보이게 했습니다.

## 7. 검증

### 7-1. 회귀 테스트 — **37개 파일 503건 전부 통과**

이번에 새로 만든 **36건**은 위 결함들을 잠급니다. 전부 **고치기 전에는 실패하는** 형태로 적었습니다.

실제로 확인했습니다 — A-1 과 B-3 의 수정을 잠깐 되돌리고 돌려 봤더니 해당 검사 2건이 정확히 빨간불이 났고, 되돌린 것을 복구하니 다시 통과했습니다. **검사가 진짜로 그 결함을 잡는다**는 뜻입니다.

주요 검사:

- 시작 직후 곧바로 물어봐도 진행 중인 회차가 나온다 (A-1)
- `javascript://www.youtube.com/...` 을 거른다 (A-2)
- 동시에 두 번 돌려도 당첨자가 겹쳐 쌓이지 않는다 (B-1)
- 지급 실패로 되돌리면 지급일도 지운다 (B-3)
- 이미 지급된 뒤 옛 실패 건을 다시 올릴 수 없다 (B-3)
- 방송 연결만 끊고 미리보기는 남긴다 (B-4)
- 선택지를 지우면 정답 번호가 따라간다 (B-6)
- `null` · 숫자 · 글자 · 배열 본문이 전부 빈 객체가 된다 (C-3)
- 어떤 월 값을 넣어도 시작·끝이 유효한 날짜다 (C-2)
- 주민번호를 합쳐 담는 숨은 칸이 없다 (C-4)
- 14자리 주문번호는 로그에 그대로 남고, 진짜 카드번호만 가려진다 (5-1)

### 7-2. 정적 검사

- `tsc --noEmit` — **오류 0**
- `eslint` — **오류 0** (기존 경고 16건은 그대로, 미사용 인자 표기용)

### 7-3. 손대지 않은 것

후원 결제, MO 번호 발급·소급, EMMA MO/MT, 정산 금액 계산식은 건드리지 않았습니다. 오버레이 배치값의 저장 범위와 변환 방식도 그대로입니다.
